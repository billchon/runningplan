# 러닝 코스 빌더 앱 PRD (초안)

**문서 버전**: v1.3 (데이터 모델 ERD 반영)
**작성 목적**: 개인 프로젝트 / 포트폴리오

---

## 1. 개요

### 1.1 한 줄 요약
지도 위에서 나만의 러닝 코스를 직접 설계하고, 안전·편의 정보를 확인하며 도심 속 새로운 길을 탐험하듯 뛸 수 있는 러닝 앱.

### 1.2 배경 및 문제 정의
러너들은 익숙한 몇 개의 코스를 반복해서 뛰는 경향이 있다. 이는 다음과 같은 문제로 이어진다.

- 반복되는 경로로 인해 러닝에 대한 흥미와 동기가 점차 감소한다.
- 새로운 코스를 시도하고 싶어도, 그 길이 안전한지(횡단보도, 계단 등) 편의시설(화장실, 편의점, 샤워시설 등)이 있는지 미리 알기 어렵다.
- 기존 러닝앱(스트라바, 나이키런클럽 등)은 '완료된 기록 관리'에는 강하지만, '새로운 코스를 발견·설계하는 경험'은 충분히 지원하지 않는다.

### 1.3 제품 비전
사용자가 지도 위에서 직접 코스를 설계하고, 안전·편의 정보를 바탕으로 안심하고 새로운 길을 탐험하며, 도심 속에서 여행하는 듯한 즐거움을 느낄 수 있는 러닝 경험을 제공한다.

## 2. 목표 및 성공지표

| 목표 | 지표 | 목표 수치(안) | 근거 |
|---|---|---|---|
| 신규 코스 탐색 유도 | 사용자당 월평균 신규 코스 생성 수 | 월 2개 이상 | 반복 코스 탈피가 핵심 가치이므로, 최소 월 2회는 새 코스를 시도해야 가치 실현으로 판단 |
| 코스 설계 진입장벽 낮추기 | 코스 생성 완료율(시작 → 저장까지) | 60% 이상 | 일반적인 멀티스텝 폼 완료율 기준(50~70%대)을 참고한 목표치 |
| 안전정보의 실질적 도움 | 안전정보 확인 후 경유지 수정 비율 | 20~30% | 정보가 실제 의사결정에 영향을 주는지 확인하는 가설적 지표 |
| 러닝 지속률(리텐션) | D1 / D7 / D30 리텐션 | D1 30%+, D7 15%+, D30 5~7% | 헬스/피트니스 카테고리 D30 벤치마크(3~7%)의 상단을 목표로 설정 |
| 제품-시장 적합성(PMF) 신호 | D14 이후 리텐션 커브 평탄화 지점 | 7% 이상에서 평탄화 | Amplitude의 "7% 룰" — 커브가 이 선에서 평탄해지면 핵심 유저층 확보 신호로 해석 |

**D1 / D7 / D30 리텐션이란?** 앱을 처음 사용한 날을 기준으로 며칠 뒤에도 다시 돌아오는 유저 비율을 뜻한다.
- D1: 설치 다음 날 재방문 비율 — 온보딩(첫 사용 경험)이 잘 됐는지를 보여줌
- D7: 설치 후 7일째 재방문 비율 — 습관이 형성되기 시작했는지를 보여주는 가장 진단적인 지표
- D30: 설치 후 30일째 재방문 비율 — 일회성 호기심을 넘어 실제 루틴으로 자리잡았는지를 보여줌

> 📌 헬스/피트니스 카테고리는 소셜(D30 15~20%), 생산성(D30 10~18%) 등 다른 카테고리보다 구조적으로 리텐션이 낮은 편이라, D30 5~7%는 낮은 수치가 아니라 카테고리 내에서는 상위권 목표에 해당한다.

## 3. 타겟 사용자

### 3.0 시장 맥락 (근거 데이터)

- 한국갤럽 조사 기준 국내 러닝 인구는 2025년 1000만 명을 넘어선 것으로 추정되며, 조깅·달리기 경험률은 2021년 23%에서 2023년 32%로 상승. 다만 문화체육관광부의 공식 국민생활체육조사 기준으로는 2025년 러닝 참여율이 인구의 7.7% 수준(약 375만 명)으로, 더 보수적이고 신뢰할 만한 통계로 평가됨
- 문체부 조사에서 '달리기' 참여 비율은 2024년 4.8%에서 2025년 7.7%로 1년 새 큰 폭 상승 — 단순 유행이 아닌 생활형 운동으로 확산되는 신호
- 2030세대를 중심으로 러닝 붐이 일고 있으며, 러닝크루 같은 커뮤니티가 빠르게 확산
- 국내 러닝앱 이용자 수(런데이·나이키런클럽 기준)는 월 30만 명 이상, 러닝 관련 검색량은 반년 새 270% 증가

**시사점**: 러닝 인구가 빠르게 늘고 있으며 신규 유입이 활발한 시기 — 기존 페르소나(반복에 지친 러너, 탐험을 즐기는 러너)에 더해 막 러닝을 시작한 입문자도 무시할 수 없는 비중

### 3.1 대상
전체 러너 대상 (범용) — 입문자부터 숙련자까지, "새로운 코스에 대한 갈증"이 있는 모든 러너.

### 3.2 페르소나 (예시, 추후 리서치로 보완 필요)

**페르소나 A. 반복에 지친 직장인 러너**
- 퇴근 후 항상 같은 공원 코스만 뛰다 보니 최근 러닝 빈도가 줄어듦
- "오늘은 다른 길로 뛰어볼까?" 하다가도 낯선 길이 안전한지 몰라 포기

**페르소나 B. 탐험을 즐기는 러너**
- 여행 가서도 그 도시를 뛰며 구경하는 걸 좋아함
- 자신이 직접 짠 코스를 기록하고 공유하는 데 흥미를 느낌

**페르소나 C. 러닝 붐에 올라탄 입문 러너**
- 최근 러닝을 막 시작했고, 러닝크루나 SNS 영향으로 유입된 2030세대
- 어디서 뛰어야 할지, 안전한 코스인지 판단 기준이 없어 유명 장소(한강 등)만 반복

## 4. 핵심 기능 명세 (MVP)

MVP는 아래 핵심 기능들로 구성됩니다.

**전체 화면 구성**: 로그인 → 신체정보 입력(최초 1회) → 홈 화면(코스 만들기 버튼+코스 선택) → 코스 빌더 → 코스 정보(자동저장) → 코스 목록/더보기(코스별 인라인 시작 버튼) → 러닝 트래킹 → 결과 요약 / 홈에서 성장 리포트로 진입 가능

### 4.0 로그인

앱 최초 진입 시 거치는 인증 흐름. **카카오/구글 소셜 로그인만 지원한다 (2026-08-05 결정, 이메일/비밀번호 로그인 제외)** — 소셜 로그인은 최초 로그인 시 자동으로 계정을 생성하므로 별도의 회원가입 화면이 없다. 신장·체중 등 신체 정보는 최초 로그인 직후에만 별도 단계에서 입력받는다.

**User Story**
- 사용자는 앱 최초 진입 시 로그인 화면을 마주하며, 카카오 또는 구글 계정으로 로그인할 수 있다.
- 처음 로그인하는 사용자는 로그인 직후 이어지는 화면에서 신장·체중을 입력한다. 이미 입력을 마친 사용자는 로그인 시 바로 홈 화면으로 이동한다.
- 사용자는 로그인 상태를 유지하여 다음 실행 시 재로그인 없이 앱을 사용할 수 있다.

**주요 화면 (안)**
1. 로그인 화면 — 카카오/구글 로그인 버튼만 존재
2. 신체정보 입력 화면 — 최초 로그인 직후에만 진입, 신장·체중 입력

**오픈 이슈**
- 신장·체중은 민감정보에 준하는 개인정보이므로, 저장·처리 시 관련 법령(개인정보보호법) 준수 및 수집 목적(운동량 제안) 고지 필요
- 신체정보 입력 단계에서 건너뛰기(skip) 허용 여부 결정 필요
- 카카오/구글 OAuth는 각 콘솔에 앱 등록 + Supabase Dashboard의 Provider 설정(Client ID/Secret, Redirect URL 등록)이 선행되어야 동작함 — 2026-08-05 기준 코드는 준비됐으나 앱 등록 전이라 실제 로그인은 아직 불가

### 4.1 홈 화면

앱 진입 시 첫 화면. 빠른 러닝 시작, 저장된 코스 바로가기, 주간 요약 통계, 성장 리포트 진입점을 제공.

**User Story**
- 사용자는 홈 화면에서 "나만의 러닝 코스 만들기" 버튼으로 코스 빌더 화면에 바로 진입할 수 있다.
- 사용자는 홈 화면의 "코스 선택" 섹션에서 저장된 코스 목록과 자유 러닝 항목을 확인하고, 각 항목 옆 시작 버튼으로 바로 러닝을 시작할 수 있다. "더보기"를 눌러 전체 코스 목록으로 이동할 수 있다.
- 사용자는 홈 화면에서 이번 주 러닝 요약(횟수, 총 거리, 신규 코스 수)을 확인할 수 있다.
- 사용자는 홈 화면에서 성장 리포트 화면으로 진입할 수 있다.


### 4.2 코스 빌더

지도 위에서 포인트(경유지)를 지정하면 도로 기반으로 경로가 자동 생성되는 기능.

**User Story**
- 사용자는 지도에서 시작점 · 경유지 · 도착점을 탭하여 경로를 만들 수 있다.
- 사용자는 지정한 포인트를 기반으로 자동 생성된 경로(도로 기반)를 확인할 수 있다.
- 사용자는 생성된 경로의 예상 거리와 소요 시간을 확인할 수 있다.
- 사용자는 경유지를 추가·삭제·이동하며 경로를 수정할 수 있다.
- 사용자는 코스 정보 화면에서 스타트/골인 지점의 위치 태그(행정동 + 주변 건물명)를 자동으로 확인할 수 있다. 지역이 2개 이상 걸치는 경우 모두 표시되며, 스타트와 골인 지점이 동일한 경우 출발지 지역 태그와 함께 "순환"으로 표시된다.
- 사용자는 코스 정보 화면에서 1km 구간이 표시된 경로와 평균 페이스를 확인할 수 있다.
- 사용자는 코스 이름과 메모를 입력할 수 있으며, 별도의 저장 버튼 없이 자동으로 저장된다.
- 사용자는 경관·안전·평탄 등 여러 항목별로 나누어 5점 만점 평가를 남길 수 있다.
- 사용자는 코스 목록 화면에서 자동 저장된 코스의 정보(이름, 메모, 평점 등)를 다시 수정할 수 있다.

**주요 화면 (안)**
1. 코스 빌더 화면 — 지도 위 포인트 탭으로 경로 생성, 예상 거리/시간 표시
2. 코스 정보 화면 — 위치 태그(자동), 1km 구간 표시 경로, 이름/메모 입력, 항목별 평점, 자동저장 안내
3. 코스 목록 화면 — 저장된 코스 목록(이름/평균 페이스/평점) 및 수정 진입점

### 4.3 안전 · 편의정보 오버레이

생성된 경로 위에 편의시설, 대중교통, 위험 요소 정보를 함께 보여주는 기능.

**User Story**
- 사용자는 경로 주변의 편의시설(주차장, 편의점, 화장실, 샤워시설 등)을 지도 위 아이콘으로 확인할 수 있다.
- 사용자는 경로 주변의 지하철역, 버스정류장 등 대중교통 정보를 지도 위 아이콘으로 확인할 수 있다.
- 사용자는 경로 상의 횡단보도, 계단 등 이동에 영향을 주는 요소를 확인할 수 있다.
- 사용자는 이 정보를 바탕으로 코스 설계 단계에서 경유지를 조정할 수 있다.

**주요 화면 (안)**
1. 경로 미리보기 화면에 편의시설/안전정보 레이어 토글 추가
2. 지도 아이콘 탭 시 상세 정보(운영시간 등) 팝업

**오픈 이슈**
- 화장실/횡단보도/주차장/버스정류장/지하철역은 공공데이터포털 표준데이터로 확보 가능. 편의점(민간 상업시설)은 카카오/T맵 로컬 API POI로, 계단·샤워시설은 전용 공공데이터가 없어 OSM 보완 또는 사용자 제보 방식 검토 필요

### 4.4 러닝 트래킹 (완주 확인)

설계한 코스를 따라 실제로 뛰고, GPS로 기록하며 완주 여부를 확인하는 기능.

**User Story**
- 사용자는 코스 선택 화면에서 각 코스 항목 옆에 배치된 시작 버튼을 눌러 바로 러닝을 시작할 수 있다.
- 사용자는 러닝 중 실시간으로 GPS 기반 위치·거리·페이스를 확인할 수 있다.
- 사용자는 러닝 종료 시 설계한 코스를 얼마나 따라 뛰었는지(완주율)를 확인할 수 있다.
- 사용자는 러닝 종료 시 별도의 저장 버튼 없이 완주한 코스와 기록(거리, 시간, 페이스)이 자동으로 저장되며, 목록 화면에서 다시 보고 수정할 수 있다.
- 사용자는 러닝 결과 화면에서 1km 구간마다 표시된 경로를 확인할 수 있다.
- 사용자는 러닝 결과 화면에서 구간별 속도에 따라 색으로 구분된 경로(빠름: 녹색, 보통: 파란색, 느림: 빨간색)를 확인할 수 있다.

**주요 화면 (안)**
1. 러닝 시작 전 코스 선택 화면
2. 러닝 중 실시간 트래킹 화면 — 실시간 위치/거리/페이스, 계획 코스 대비 완주율
3. 러닝 종료 후 결과 요약 화면 — 1km 구간 표시 및 구간별 속도 색상(빠름/보통/느림) 경로, 거리/시간/평균 페이스/완주율
4. 코스 목록 화면 (4.2와 공유) — 완주한 러닝 기록 확인 및 수정

### 4.5 성장 리포트

사용자의 누적 러닝 활동을 분석하여 최장 거리, 평균 거리, 평균 페이스 등의 변화를 그래프로 보여주는 기능.

**User Story**
- 사용자는 성장 리포트 화면에서 기간별(주/월) 최장 거리 기록 변화를 그래프로 확인할 수 있다.
- 사용자는 성장 리포트 화면에서 기간별 평균 거리 변화를 그래프로 확인할 수 있다.
- 사용자는 성장 리포트 화면에서 기간별 평균 페이스 변화를 그래프로 확인할 수 있다.

**주요 화면 (안)**
1. 성장 리포트 화면 — 최장 거리/평균 거리/평균 페이스 추이 그래프

**오픈 이슈**
- 그래프 집계 주기(주간/월간)와 표시 기간(최근 3개월/6개월/전체) 결정 필요
- 향후 신장·체중 기반 "적정 운동량 제안" 기능과의 연계 구조 설계 필요 (MVP 이후 로드맵 항목)

## 5. MVP 이후 로드맵 (Out of Scope for MVP)

아래 기능들은 MVP에는 포함하지 않으며, 이후 단계에서 검토합니다.

- **코스 추천**: 다른 사용자가 기록한 코스를 추천받는 기능
- **탐험 지도 게이미피케이션**: 뛴 지역이 지도 위에 시각적으로 넓어지는 방식(정복률, Fog of War 형태 등)으로 동기를 부여하는 기능
- **러닝 영상/사진 자동 편집**: 러닝 중 촬영한 사진·영상을 자동으로 편집(하이라이트 생성 등)하여 러닝 기록을 콘텐츠로 남길 수 있게 하는 기능
- **해외 러닝 지원**: 해외 여행 중에도 코스 설계·러닝이 가능하도록 Google Maps 기반 경로 계산을 지원 (단, 경로 계산 모듈을 지역별로 교체 가능하게 하는 아키텍처는 MVP 단계부터 미리 반영)
- **적정 운동량 제안**: 회원가입 시 입력받은 신장·체중과 누적 활동 데이터를 바탕으로 사용자에게 맞는 운동량을 제안하는 기능 (신장·체중 데이터 자체는 MVP에서 수집)

## 6. 비기능 요구사항 (초안)

| 항목 | 내용 |
|---|---|

| 지도 데이터 | 국내: **네이버지도 SDK**(`@mj-studio/react-native-naver-map`, 시각화) + T맵 보행자 경로 API(경로 계산) / 해외: Google Maps SDK + Compute Routes API(도보 모드) — MVP는 국내(T맵) 기준으로 개발하되, 해외 확장을 고려해 경로 계산 모듈을 지역별로 교체 가능한 구조(추상화 레이어)로 초기 아키텍처 설계 단계부터 반영. 카카오맵은 공식 RN SDK가 없고 커뮤니티 래퍼도 임베디드 렌더링을 지원하지 않아 제외 (2026-08-04 결정, 근거는 7장 참고) |
| 개발 워크플로우 | 네이버지도 SDK는 네이티브 모듈이라 Expo Go에서 동작하지 않음 — Development Build(`expo prebuild` + `expo run:ios/android` 또는 EAS Build)로 전환 필요 |
| 위치 태그(역지오코딩) | 스타트/골인 좌표를 행정동+주변 건물명으로 변환하기 위해 카카오 로컬 API 또는 T맵 지오코딩 API 등 역지오코딩 API 연동 필요 |
| 위치정보 | GPS 기반 실시간 트래킹, 백그라운드 위치 권한 필요 |

- 도로 기반 자동 경로 생성 시, 러닝에 부적합한 경로(차도 등)를 걸러내는 로직 필요

## 10. 데이터 모델 (ERD)

| 테이블 | 주요 필드 | 설명 |
|---|---|---|
| USERS | id, email, login_provider, height_cm, weight_kg | 사용자 계정 및 신체 정보 |
| COURSES | id, user_id(FK), name, memo, distance_m, avg_pace, is_circular | 저장된 코스 정보 |
| COURSE_WAYPOINTS | id, course_id(FK), seq, lat, lng | 코스를 구성하는 경유지 좌표 |
| COURSE_RATINGS | id, course_id(FK), category, score | 코스에 대한 항목별(경관/안전/평탄) 평점 |
| COURSE_LOCATION_TAGS | id, course_id(FK), tag_type, region_name | 코스의 스타트/골인 위치 태그 |
| RUNS | id, user_id(FK), course_id(FK, nullable), distance_m, duration_sec, completion_rate | 러닝 실행 기록 (코스 기반 또는 자유 러닝) |
| RUN_SEGMENTS | id, run_id(FK), km_index, pace, speed_category | 러닝 기록의 1km 구간별 페이스/속도 구분 |

**관계 요약**
- USERS 1:N COURSES, USERS 1:N RUNS
- COURSES 1:N COURSE_WAYPOINTS / COURSE_RATINGS / COURSE_LOCATION_TAGS
- COURSES 1:N RUNS (하나의 코스로 여러 번 러닝 가능, RUNS.course_id는 자유 러닝의 경우 nullable)
- RUNS 1:N RUN_SEGMENTS (구간별 페이스 색상 표시에 사용)
